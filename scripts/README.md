# TEI Register Enrichment Scripts

Scripts for enriching the TEI-XML person register of *schleiermacher digital* with gender information and separating institution entities into their own register.

## Prerequisites

- Python 3.11+ with a virtual environment (`.venv/`)
- `lxml` (`pip install lxml`)
- Input data:
  - **Person register**: `data/raw/schleiermacher/Register/Personen/A.xml` … `W.xml` (fresh eXist-DB export)
  - **Letter files**: `data/raw/schleiermacher/Briefe/**/*.xml`
  - **Other registers**: `data/raw/schleiermacher/Register/Werke.xml`, `Glossar.xml`, `Orte.xml`
  - **Gender CSV**: `data/output/gender_reviewed.csv` (output of the genderTagger classification + review pipeline)

All paths are relative to the `current/` project root.

## Pipeline Overview

Run the three scripts in order on a fresh eXist-DB export:

```
1. enrich_sex.py          Add <sex> elements to person entries
2. extract_institutions.py Generate Institutionen.xml + clean person register
3. transform_persname_to_orgname.py  Rename <persName> → <orgName> in all files
```

After completion, the enriched XML files can be re-imported into eXist-DB / ediarum.

---

## Step 1: `enrich_sex.py`

Inserts `<sex>` elements into `<person>` entries in the Personen register (A–Z.xml) based on gender classifications from `gender_reviewed.csv`.

### Data model

```xml
<sex value="male|female" evidence="assigned" resp="#fko|#gendertagger" cert="high|low"/>
```

### Rules

| Attribute  | Value |
|------------|-------|
| `value`    | `corrected_gender` if non-empty, else `predicted_gender` |
| `evidence` | Always `assigned` (historical assignment, not self-identification) |
| `resp`     | `#fko` if review_status is `corrected` or `verified`; `#gendertagger` otherwise |
| `cert`     | `high` if human-reviewed or automated with cert=high; `low` if automated with cert=single |

Entries with gender = `unknown`, `institution`, or empty are skipped.

### Placement

After the last `<persName>` child of each `<person>`, before `<birth>`/`<death>`/`<note>`.

### Usage

```bash
# Preview changes
python scripts/enrich_sex.py --dry-run

# Apply changes
python scripts/enrich_sex.py

# Custom paths
python scripts/enrich_sex.py --csv path/to/gender_reviewed.csv --xml-dir path/to/Personen/
```

### Technical note

Uses line-based string insertion (not lxml serialization) to preserve the original XML formatting exactly.

## Step 2: `extract_institutions.py`

Extracts all entries classified as `institution` from the Personen register, transforms them into `<org>` elements, and writes a new `Institutionen.xml` register. Then optionally removes those entries from the source files.

### Transformation mapping

| Source element | Target element |
|----------------|----------------|
| `<person xml:id>` | `<org xml:id>` |
| `<persName type="reg"><surname>…</surname><forename>…</forename></persName>` | `<orgName type="reg">surname, forename</orgName>` |
| `<persName type="alt">` | `<orgName type="alt">` |
| `<note>` | `<desc>` (preserves mixed content) |
| `<idno>` | `<idno>` (kept as-is) |
| `<birth>`, `<death>`, `<sex>` | Dropped |

### Group handling

- Pure-institution groups → `<listOrg>` with `<head>` and `<org>` children
- Mixed groups (institutions + persons) → institution members extracted as standalone `<org>`
- Top-level institutions → standalone `<org>`

### Usage

```bash
# Generate Institutionen.xml (read-only, source files untouched)
python scripts/extract_institutions.py

# Preview which entries would be removed from source files
python scripts/extract_institutions.py --clean --dry-run

# Remove institution entries from Personen A-Z.xml
python scripts/extract_institutions.py --clean
```

### Output

- `data/raw/schleiermacher/Register/Institutionen.xml` — the new institution register (~120 entries)

## Step 3: `transform_persname_to_orgname.py`

Walks all XML files recursively and renames `<persName>` → `<orgName>` wherever the `key` attribute references an institution ID. Also renames `indexName="persons"` → `"institutions"` on matching `<index>` elements.

### Three transformations

1. **Normal persName**: `<persName key="INST">…</persName>` → `<orgName key="INST">…</orgName>`
2. **Self-closing**: `<persName key="INST"/>` → `<orgName key="INST"/>`
3. **Index elements**: `<index indexName="persons" corresp="INST">` → `indexName="institutions"`

### Multi-key handling

If a `<persName>` has both institution and person keys (e.g. `key="S_inst S_person"`), it wraps:

```xml
<orgName key="S_inst"><persName key="S_person">…</persName></orgName>
```

(Currently no such cases exist in the corpus, but the logic is implemented.)

### Institution ID source

Reads `xml:id` attributes from all `<org>` elements in `Institutionen.xml` (generated by Step 2).

### Exclusions

- `Institutionen.xml` itself (contains `<persName key="…">` references to actual persons in `<desc>` elements)
- `Personen/` directory (already cleaned in Step 2)

### Usage

```bash
# Preview all changes
python scripts/transform_persname_to_orgname.py --dry-run

# Apply changes
python scripts/transform_persname_to_orgname.py

# Apply + validate XML well-formedness of modified files
python scripts/transform_persname_to_orgname.py --validate

# Custom target directory
python scripts/transform_persname_to_orgname.py --dir path/to/xml/root/

# Exclude additional directories
python scripts/transform_persname_to_orgname.py --exclude-dir Tageskalender
```

### Technical note

Uses Python regex with `re.DOTALL` (not lxml serialization) to handle multi-line `<persName>` elements while preserving the original XML formatting byte-for-byte outside of the changed tags.

## Expected Results

After running the full pipeline on the current corpus:

| Metric | Value |
|--------|-------|
| Institution entries extracted | ~120 |
| Person register files cleaned | 21 (A.xml – W.xml) |
| `<sex>` elements added | ~7,900 |
| Files with persName→orgName changes | ~660 |
| persName→orgName renames | ~920 |
| index persons→institutions renames | ~55 |
| Distinct institution IDs matched | ~73 (of 120) |
